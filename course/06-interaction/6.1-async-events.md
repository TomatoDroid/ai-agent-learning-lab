## 拆解

### 回合制是一种约定

前五章里，用户说一句，Agent 想一段、调几个工具、回一句，**世界被默认为静止的**。真实环境不会等：邮件在它思考时到达，用户在它说到一半时插话。这一章沿着两根轴往外推：

| 轴 | 决定什么 | 本章的扩展 |
| --- | --- | --- |
| 模态 | 观察和动作的**形式** | 语音、屏幕、物理传感器；说话、点击、关节运动 |
| 触发时机 | 观察和动作的**节奏** | 世界主动推送；动作跨回合、可打断、可抢占 |

这一课只动时机，模态仍然是文本。后两课再把时间尺度从“秒到天”压到毫秒。

### 三种事件处理策略

<div class="anim" data-anim="event-strategies">▶ 动画“三种事件处理策略：打断、排队、并行”需要在课程网站中观看。</div>

事件循环在同步接口下的骨架是：**事件在每轮循环的边界被消费**。模型推理、工具执行期间，新事件先等着，到达一个**安全点**（一段推理结束、一次工具返回）再处理。三种策略的区别只在“等不等安全点”：

| 策略 | 用于 | 做法 | 例子 |
| --- | --- | --- | --- |
| 取消式 | 紧急事件 | **提前制造**一个安全点：停掉当前步骤，排队的事件和紧急事件一起追加，立即重新调用模型 | 用户：“停！我说错了” |
| 队列式 | 常规事件 | 等下一个**自然的**安全点，批量追加 | 搜索期间用户补充“只看最近一个月” |
| 并行式 | 无关的轻量查询 | **另起一个**推理会话，不等主循环 | 分析数据时用户问“今天天气怎么样” |

紧急：`user.interrupt`、`supervisor.instruction`、`agent.interrupt`、标记为紧急的外部触发器。非紧急：`user.input`、`tool.result`、`timer.trigger` 和常规外部触发器。硬规则总有例外（“马上停下来”和“报告用中文发我”都是 `user.input`），所以原书建议用**轻量级的分类 LLM 当路由器**。

处理的前提是理解：每个输入都要建模成带**来源、渠道、内容、上下文**的结构化事件。少了来源，模型就可能把用户的话当成工具结果，或者把工具结果里藏的指令当成用户指令（2.3 课的提示注入）。

### 打断时的占位符

<div class="anim" data-anim="interrupt-placeholder">▶ 动画“打断时的占位符：让轨迹合法，又不让模型编造”需要在课程网站中观看。</div>

如果接口要求每个工具调用后面都有配对结果，打断就会撞上格式。兼容方案的核心：**常态下让模型看到标准的同步轨迹，只在打断时插入占位符修复格式**。五条规则：

1. API 完成的 assistant 消息和工具调用项**及时记录**；服务端管理的 reasoning 按厂商协议保留，不自行拼接。
2. 工具**完成时**才记录 tool result。
3. 工具执行中被打断：为未完成的调用生成**占位符**，追加打断事件，重新调用模型。
4. 没有原生 steering 时，取消未完成的生成，保留已确认的部分，追加新事件后重新请求；**不能把半截输出当合法前缀回灌**。
5. 非打断事件进队列，等当前周期完成后一次性追加。

占位符有语义风险：模型可能把“已启动”当成“已完成”。所以占位符要说清“没完成、结果另行送达、别假设它”，迟到的结果要带**来源和任务 ID**，评估时要专门检查**是否编造了未到达的数据**。

更根本的办法在工具设计上：把“启动”和“完成”拆开。`initiate_phone_call` 立即返回任务 ID 和初始状态，进展通过 `phone_call_connected`、`phone_call_ended` 事件通知。这样“启动任务”本身就是一次有真实返回值的完整调用，占位符都不需要。

批量追加还有一个坑：**注意力分散**，模型容易只回应最后一个事件。办法是 Agent 状态栏标记：每个事件前加 `[未处理事件 i/n]`，末尾汇总“上面有 n 个未处理事件，包括……请确保回应涵盖所有信息”。

### 模型原生异步

<div class="anim" data-anim="native-async">▶ 动画“模型原生异步：等待不阻塞，中途可以改需求”需要在课程网站中观看。</div>

| 能力 | 解决什么 | 不解决什么 |
| --- | --- | --- |
| 异步工具调用 | 发起行动和获得结果分开：等待期间继续做不依赖结果的工作 | 依赖关系要模型自己分清 |
| 回合中途引导 | 用户不必等一整轮结束就能补充要求 | 改计划不等于停止工具，更不会撤销已发生的动作 |

两条路线都**仍然需要运行时**管理事件来源、工具生命周期和结果归属。可靠性要检查三件事：迟到的结果能否归入正确任务、缺席时不编造；处理新要求后能否回到原任务、分清“改计划”和“停止”；多条更新能否**同时**遵守。

三个练习都做完后，想看它跑起来，在 `mini-agent/` 下运行这段（假模型，不需要 API Key）：

```python
import asyncio
from mini_agent import llm as L
from mini_agent.events import Event, EventLoopAgent
from mini_agent.tools import Tool, ToolRegistry

async def main():
    async def search_contacts(name):
        await asyncio.sleep(1)           # 一个慢工具
        return f"{name} <zhang@example.com>"
    reg = ToolRegistry()
    reg.register(Tool("search_contacts", "查联系人", {"type": "object", "properties": {"name": {"type": "string"}}}, search_contacts))
    llm = L.ScriptedLLM([L.call("search_contacts", "c1", name="张三"), L.say("明天晴。"), L.say("草稿：致 zhang@example.com……")])
    agent = EventLoopAgent(llm, reg)
    agent.post(Event("user.input", "给张三写封邮件"))
    task = asyncio.create_task(agent.run())
    await asyncio.sleep(0.1)
    agent.post(Event("user.input", "等一下，先查明天天气", priority="urgent"))
    await task
    print(agent.outbox, agent.log, sep="\n")
    for m in llm.calls[-1]["messages"]:
        print(m["role"], "|", m.get("content"))

asyncio.run(main())
```

## 检验（先闭卷回答，再展开）

<details>
<summary>1. 什么是安全点？三种策略分别怎样对待它？</summary>

安全点是可以消费新事件的边界：一段推理结束、一次工具返回。队列式等下一个自然出现的安全点；取消式为紧急事件提前制造一个安全点（停掉当前步骤）；并行式另起一个循环，不必等主循环的安全点。
</details>

<details>
<summary>2. 为什么打断时要插占位符，而不是伪造一个结果或直接追加新消息？</summary>

直接追加会留下没有配对结果的工具调用，要求配对的接口会直接拒绝请求。伪造结果格式合法，但模型会基于不存在的数据行动。占位符既维持配对，又明确告诉模型“没完成、结果另行送达、别假设它”；真实结果到达后，以带来源和任务 ID 的事件送入轨迹。
</details>

<details>
<summary>3. 用户点“停止”和用户说“等一下，先查天气”，处理有什么不同？</summary>

都是取消式。前者是 `user.interrupt`：未完成的工具被真的取消，占位符写“已被用户取消”，之后没有迟到的结果。后者只是改变优先级：工具转入后台继续跑，结果晚到后作为事件送回，原任务接着完成。另外，“停止”消息本身不会撤销已经发生的动作，取消要靠执行器响应取消信号。
</details>

<details>
<summary>4. 批量追加事件时会出什么问题？怎么缓解？</summary>

注意力分散：模型容易只回应最后一个事件，遗漏前面的要求。提示词层面告诉模型综合考虑所有事件；结构上给每个事件加 `[未处理事件 i/n]` 标记，末尾汇总各类事件的数量，要求回应涵盖所有信息。
</details>

<details>
<summary>5. 原生异步能力出现后，兼容方案和运行时还有必要吗？</summary>

有。不是所有模型都支持原生能力；即使支持，事件来源、工具生命周期、取消、状态查询和结果归属仍由运行时负责。原生异步解决的是消息能否在运行中到达，可靠性还要看模型能否正确归属结果、不编造缺席的数据、同时遵守多条更新。
</details>

<details>
<summary>6. 为什么要把 phone_call 设计成 initiate_phone_call 加事件？</summary>

“调用即完成”的命名会让模型以为调用结束时电话已经打完。拆成“启动”和“完成”后，启动调用立即返回任务 ID 和初始状态，本身就是一次有真实返回值的完整调用；进展通过事件到达。名称和描述本身就传达了异步语义，同步接口下也不需要占位符。
</details>

## 复盘卡

> **前提**：回合制是交互约定，不是环境性质；这一课只扩展时机。
> **事件**：结构化建模（来源、渠道、内容、上下文）；事件触发工具让世界唤醒 Agent，用户沟通工具让 Agent 触达用户。
> **策略**：紧急 → 取消式（提前制造安全点）；常规 → 队列式（等自然安全点，批量追加，加标记防注意力分散）；无关轻量 → 并行式（另起会话，记录并入主轨迹）。
> **兼容方案**：常态是标准同步轨迹；打断时为未完成的调用补占位符；真实结果带任务 ID 作为事件送回；绝不伪造成功。
> **原生异步**：发起与获得结果分开、中途可以引导；运行时仍负责执行、取消和归属。
