## 拆解

### 五类工具

| 工具类型 | 调用方向 | 作用对象 | 设计关键 |
| --- | --- | --- | --- |
| 感知 | Agent 主动调用 | 获取信息 | 控制输出信息量（4.3 课） |
| 执行 | Agent 主动调用 | 改变世界 | 安全约束（4.3 课） |
| 协作 | Agent 主动调用 | 驱动其他 Agent 或人类 | 生命周期原语（4.3 课、第十章） |
| 用户沟通 | Agent 主动调用 | 向用户传递信息 | 跨渠道异步触达（第六章） |
| 事件触发 | Agent 注册、外部触发 | 驱动 Agent 开始执行 | 事件驱动运行时（第六章） |

这些原则统称 **ACI**（Agent-Computer Interface），对标 HCI：工具要对应 Agent 的**目标**，而不是把每个 API 端点各包成一个工具。

### 能力的三种形态

<div class="anim" data-anim="capability-forms">▶ 动画“同一项能力，三种形态”需要在课程网站中观看。</div>

**默认取向：通用优于专用，除非有明确的安全、权限或性能理由。** 与其提供一个四则运算计算器，不如给一个装好 numpy、sympy 的 `code_interpreter`。即使要专用工具，粒度也偏向整合：`extract_pdf_text`、`extract_docx_content` 合并成一个带 `file_type` 参数的 `read_document`。

| 维度 | 偏专用工具 | 偏 Skill + 通用执行器 |
| --- | --- | --- |
| 安全与权限 | 需要精细授权、审计、不可逆 | 其余情况 |
| 参数复杂度 | 嵌套对象、多字段联合校验 | 参数简单，CLI 传参也可靠 |
| 变更频率 | 稳定的底层操作 | 频繁变化（改一段文字就行） |
| 模型能力 | 较弱的模型需要 schema 引导 | 较强的模型 |

为什么参数复杂时要退回专用工具？原生工具调用用 JSON，有的推理引擎还会用受限采样强制格式合法；Skill 让模型拼命令行，要处理各平台不同的引号转义，更容易出错。折中办法是让 Agent 把复杂参数写进 JSON 文件，再在命令行里读这个文件。

还有两点要分清。第一，**形态和数量是两个独立决策**：形态决定每条能力常驻多少 token、参数怎么传；一次让模型看见多少条，是 4.2 课的“披露”问题。第二，通用执行器还能**用代码编排工具调用**：一次写好脚本，中间结果留在执行环境的变量里，只把汇总结果返回上下文，token 消耗可以降低约两个数量级。这是第五章“代码作为元能力”的伏笔。

### 工具描述：写“什么时候用”和“做不到什么”

<div class="anim" data-anim="tool-description">▶ 动画“工具描述：写‘什么时候用’和‘做不到什么’”需要在课程网站中观看。</div>

| 要写的 | 为什么 | 例子 |
| --- | --- | --- |
| 什么时候用 | 帮模型做调用决策，而不只是知道功能 | “需要实时信息或查找未知事实时使用” |
| 边界 | 大多数失败是不知道工具**不能**做什么 | “只匹配文件名，不能搜索内容” |
| 具体示例 | 复杂任务里模型只能分出一点注意力看格式 | `+8613888888888`，而不只是“E.164 格式” |
| 返回值 | 减少后续解析出错 | “JSON 数组，每项有 title、url、snippet” |
| 执行代价 | 帮模型规划顺序 | “可能需要 5–10 秒；只要元信息请用 …” |

再进一步，附上 1–5 个真实调用示例：JSON Schema 只能描述类型，说不清“时间戳是秒还是毫秒”“过滤条件怎么嵌套”这类隐式约定。这些原则同样适用于 Skill 的 description。

### 参数保真：不悄悄修正，快速失败

<div class="anim" data-anim="param-fidelity">▶ 动画“参数保真：模型看到的世界，必须就是工具操作的世界”需要在课程网站中观看。</div>

书里的原则：**模型感知到的世界与工具操作的世界之间，不能存在系统性的偏差。** 两种违规：

- **静默输入转换**：传输层把弯引号换成直引号，模型反复替换失败，却无从诊断。
- **静默参数注入**：bash 工具悄悄给 `git commit` 追加参数，旧版 Git 报错，模型怎么改提交信息都没用。

如果确实要规范化，必须写进描述，并在返回值里告诉模型。反过来，工具拿到不合法的参数时，正确做法是**快速失败**，并把错误说清楚：错误信息本身就是给模型的观察（1.2 课）。这正是你接下来要写的。

## 延伸（Builder）

- 挑一个你常用的 MCP 服务器或 API，用 `lint_description` 检查它的工具定义，按本课的五项重写其中最差的一个。
- 给 mini-agent 加一个 `read_document(path, file_type)` 工具，体会“整合而不是细分”。
- 找一个你用过的工具，想想它有没有“静默修正”参数的行为（自动去空格、自动转大小写、自动补全路径……），它在描述里说了吗？

## 检验（先闭卷回答，再展开）

<details>
<summary>1. “默认通用优于专用”的理由是什么？什么时候该退回专用工具？</summary>

LLM 本身会思考、会写代码，一个通用执行器就能代替几十个特定工具，还能处理没预料到的边缘情况。四种情况退回专用工具：需要精细权限和审计的操作；需要屏蔽平台差异、给出更好反馈的操作（比如专门的 grep）；使用频率极高的操作；参数结构复杂、需要 schema 引导的操作。
</details>

<details>
<summary>2. 为什么说“形态”和“披露”是两个独立的决策？</summary>

形态决定每条能力的常驻成本和传参方式；披露决定同时有多少条能力摆在模型面前。几百个专用工具可以只暴露索引、按需加载；几十个 Skill 也可以全量常驻。Skill 的目录条目便宜，只是让全量常驻的可行边界远了一些，并没有替你做出披露策略。
</details>

<details>
<summary>3. Agent 频繁选错工具，第一步该做什么？</summary>

先检查工具描述：边界清不清楚、有没有反例、参数含义是否模糊。原书说大多数选择错误的根因在描述，修描述的投入产出比通常远高于换一个更强的模型。
</details>

<details>
<summary>4. 弯引号被静默转换后，模型为什么会陷入反复失败？</summary>

读取工具原样返回弯引号，模型照着复制，传输层却把它换成直引号，文件里匹配不到。模型看到的内容和工具操作的内容不一致，而这个差异发生在模型看不到的地方，所以它无论怎么重试都无法诊断。
</details>

<details>
<summary>5. 参数校验发现 <code>days="3"</code>，为什么不顺手转成整数 3？</summary>

这就是一次“智能修正”：这次碰巧对了，下次也许把 `"03"`、`"3天"` 转出意料之外的值，而模型不知道发生了什么。快速失败并说明“应该是 integer，你给的是 string '3'”，模型下一轮就能改对，世界也保持一致。
</details>

## 复盘卡

> **形态**：默认通用，安全、参数复杂、高频、平台差异四种情况退回专用；粒度偏整合。形态和披露是两件事。
> **描述**：写清什么时候用、做不到什么、能直接套用的例子、返回什么；选错工具先查描述。
> **保真**：不悄悄改参数，不悄悄加参数；不合法就快速失败，错误信息要让模型能自己诊断。
