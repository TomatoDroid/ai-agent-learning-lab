## 拆解

### 选型看的不止是成功率

| 维度 | 要点 |
| --- | --- |
| 延迟 | TTFT = 排队 + Prefill，上下文越长越慢；Decode 决定出字速度和思考时长（50 tokens/s 生成 2000 个思考 token 就是 40 秒）；看 **p95** 而不是平均值 |
| 成本 | 输入、输出、缓存分别计价；便宜但成功率低的模型要频繁重试，实际可能更贵；算每个任务的成本和成本-性能比 |
| 性能 | 日常看 Pass@1；关键操作看 Pass^k；探索性任务看 Pass@k、Best@k |
| 限流与鲁棒性 | RPM/TPM 上限、高峰期动态限额；长时运行是否注意力分散 |
| 预算—能力曲线 | RE-Bench：2 小时预算时最佳 Agent 约为人类专家 4 倍，32 小时时人类约为 Agent 2 倍。短预算领先不能外推到长任务 |
| 行为策略 | 同一 Harness 下，模型默认“先探索再改”还是“先改再用测试补”，来自后训练 |

实验 7-9 是行为策略的例子：GPT-5.6-sol 第一次修改前平均调用工具 6.89 次、读 4.67 个文件，Claude Sonnet 5 为 4.56 次、3.56 个文件；两者测试都是 100% 通过。它支持的结论是“行动策略随模型而变”，不是“多读更好”。

成本要在完整任务里实测。表 7-4 的八轮退款任务里，稳定前缀单独省 28.3%，压缩历史单独省 17.5%，一起用只省 30.0%：压缩缩短了可以命中缓存的前缀。**几项优化的节省比例不能直接相加。**

### 统计显著性：分差要超过噪声

<div class="anim" data-anim="significance">▶ 动画“70% 对 73%：是进步还是噪声？”需要在课程网站中观看。</div>

成功率 p 的标准误约为 √(p(1−p)/n)。100 道题、70% 时 95% 区间约 ±9 个点，所以“73 对 70”不足以支持切换。标准误按 1/√n 缩小：想把区间压到 ±3，需要约 900 道题。

同一批题比较两个版本，要**配对**：

- 都对、都错的题不说明谁更好，只有“一个对、一个错”的**不一致对**有信息；
- McNemar 精确检验：原假设下每个不一致对偏向哪边是抛硬币，看实际的偏向有多离谱；
- 配对 bootstrap：按题重采样，估计差值的区间；
- 每个配置跑 3–5 个种子，报告均值和波动；单次运行只用来筛方向；
- 同时验证多个假设时收紧阈值，或者对正向结果独立复跑。

实务标准一句话：**分差超过噪声、在配对分析中成立、并且能复现**，才值得据此切换模型或发布改动。

### 从 Benchmark 报告到改进

<div class="anim" data-anim="harness-iteration">▶ 动画“从 Benchmark 报告到改进：每轮只改一个变量”需要在课程网站中观看。</div>

1. **先检查评测系统，再动 Agent**：资源不足被杀进程、验证器 bug、用例与生产脱节，在数字上都和模型退化一模一样。
2. **读报告找失败簇**，不盯总分：88% 的总分下，四项 Wi-Fi 任务挂了三项。
3. **每轮只改一个变量**，固定模型、任务参数、种子、步数上限和模拟器，交替安排两组的运行顺序。
4. **一轮证据只支持与它规模相称的下一步**：子集上的 4/4 不能写成系统 100%，要在 116 项 × 5 个种子上完整复测，并设好 token 和延迟的底线。

H1 到 H5C 的教训：提示写得再详细，也补不回 Agent 根本没看到的信息；输入也不是越多越好。整个过程没换模型，只改了 Harness 怎样表示界面。

### 内部评估：AB 测试与特性开关

<div class="anim" data-anim="ab-test">▶ 动画“AB 测试：区分机制、目标和护栏”需要在课程网站中观看。</div>

| 组件 | 回答的问题 |
| --- | --- |
| 消融开关 | 这个特性真的有用，还是只是感觉有用？一个总开关关掉多个特性，得到“裸模型”基线，定期发现特性债务 |
| AB 测试 | 这次改动让目标变好了吗？多臂而非二元；区分机制指标和目标指标；设护栏；记录基线统计 |
| 双层特性开关 | 编译时开关在产物里物理移除代码；运行时开关由服务端下发、本地缓存，曝光事件每会话只记一次 |
| 提示词敏感性评估 | 哪次提交改变了渲染后的系统提示？对评估集有什么影响？提示词变更也要跑回归 |
| 隐私感知分析 | 用类型系统强制“已验证这不是代码或路径”，隐私约束从文档变成编译检查 |

AB 测试最容易犯的错误是**把你正在改变的东西当成目标**：缩短计划文件，计划长度是机制，会话成本才是目标；计划太短可能带来更多编辑—检查循环，总成本反而上升。

### 从评估到训练

一套定义清晰的验证器，本质上就是**可验证奖励（RLVR）**的奖励函数。评估环境要变成训练用的仿真环境，还要补两件事：**可靠的 reset 语义**（数百万个 episode，每个都从干净的初始状态开始，你在 7.1c 已经写过它的雏形）和**远高于评估的吞吐**（AWorld 用分布式架构把 7695 秒缩短到 525 秒）。保真度与随机化要取舍：适度的领域随机化提升泛化，过度则让任务太难。这些在模块 8 展开。

### 里程碑 B：证明一次改动真的有效

这是第二部分的第一个里程碑。从这里开始，你对 mini-agent 的每次改动都要附一份评估报告。

1. 选一处你想改的地方：系统提示里的一条规则、一个工具的描述、换一个模型，或者打开 `--coding` 时的工具集。**只改一处**。
2. 改动前后各跑一次评估，任务和试验次数相同：

   ```sh
   python -m mini_agent eval --trials 5 --save runs/before.json
   # ……做你的改动……
   python -m mini_agent eval --trials 5 --save runs/after.json
   python -m mini_agent compare runs/before.json runs/after.json
   ```

   `compare` 按（任务，第几次试验）配对，打印两边的成功率和区间、不一致对、McNemar p 值和 bootstrap 区间。
3. 写一份不超过一页的报告：改了什么（机制）、想改善什么（目标）、哪些不能变差（护栏）、结果和 p 值、你的结论。如果结论是“还分不出好坏”，写清楚下一步要加多少题或多少次试验。
4. 三条任务太少，几乎一定分不出好坏。这正是本课的教训：**往 `MINI_SUITE` 里加任务**，至少加到 15 条，再跑一次。加任务时用上 7.2 课的方法：难度分层、陷阱任务、从你自己用 `chat` 时遇到的失败里回流。

## 检验（先闭卷回答，再展开）

<details>
<summary>1. 为什么便宜的模型不一定省钱？为什么两项优化的节省不能相加？</summary>

成功率低的模型要频繁重试，每个任务的实际成本可能更高，要算任务级成本和成本-性能比。两项优化会相互影响：压缩历史的同时缩短了可以命中缓存的前缀，所以 28.3% 加 17.5% 一起用只有 30.0%，必须在完整任务里一起实测。
</details>

<details>
<summary>2. 100 道题上 70% 对 73%，怎样判断要不要切换？</summary>

先看区间：70% 时 95% 区间约 ±9，单看两个数分不出好坏。再做配对分析：逐题看不一致对，用 McNemar 或配对 bootstrap；每个配置跑多个种子；结论要能复现。预期收益只有 2–3 个点时，应先扩大评估集。
</details>

<details>
<summary>3. 同样是 70% → 73%，为什么有时显著有时不显著？</summary>

显著性取决于不一致对的结构。B 多对 3 道、没有多错，3:0 也只是 p = 0.25；B 多对 16 道、又多错 13 道，基本是抛硬币。只有不一致对足够多、又足够一边倒时才显著。
</details>

<details>
<summary>4. 看到分数下降，为什么要先检查评测系统？</summary>

资源不足被杀进程、验证器 bug、用例与生产脱节，在结果数字上都和模型退化一模一样。基于失真的信号去改 Agent，方向可能一开始就错了。只有回看完整轨迹才能区分。
</details>

<details>
<summary>5. 机制指标、目标指标、护栏指标分别是什么？决策时怎么用？</summary>

机制指标是你直接改变的东西（如计划长度）；目标指标是你真正关心的东西（如会话成本）；护栏指标是不能变差的底线（如拒绝率、满意度）。先查护栏，越线就停；再看目标指标的区间，整体大于 0 才上线。机制指标变好本身不是上线理由。
</details>

<details>
<summary>6. 评估环境变成训练用的仿真环境，还需要什么？</summary>

验证器可以直接当奖励函数。额外需要：可靠的 reset 语义，保证数百万个 episode 都从干净的初始状态开始；远高于评估的吞吐（并行、无状态的环境实例）；以及适度的随机化，防止死记硬背特定配置。
</details>

## 复盘卡

> **选型**：延迟（TTFT、decode、p95）、任务级成本、Pass@1/Pass^k/Pass@k、限流、预算—能力曲线、行为策略；优化要一起实测。
> **显著性**：SE ≈ √(p(1−p)/n)；同一批题做配对（McNemar、bootstrap），只有不一致对有信息；多种子、能复现、注意多重比较。
> **改进**：先查评测系统；找失败簇；每轮只改一个变量；一轮证据只支持相称的下一步。
> **内部评估**：消融开关、AB 测试（多臂、机制≠目标、护栏、基线）、双层特性开关、提示词回归、隐私感知分析。
> **里程碑 B**：只改一处，前后各跑 eval，用 compare 配对比较，写一页报告。
