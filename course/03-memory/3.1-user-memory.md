## 拆解

### 记忆不是聊天记录

用户记忆**不保存每句话**，而是在会话结束后用一次额外的 LLM 调用，提炼出对未来有用的事实。提炼要同时满足：

- **选择性**：丢掉“搜索返回 3 个选项”这类短期细节；
- **抽象化**：把这次“要靠窗”归纳成长期偏好；
- **结构化**：用可检索的字段保存。

轨迹和长期记忆的区别要分清：**轨迹**是单次会话的原始记录，只追加、不修改；**长期记忆**是跨会话提炼出的稳定信息，会被反复改写、合并、淘汰。前者是流水账，后者是档案。

### 先定标尺：三层次评估

| 层次 | 要求 | 例子 |
| --- | --- | --- |
| 1 基础回忆 | 准确存取用户直接给出的信息 | “我的会员号是多少？” |
| 2 多会话检索 | 从不同时间、不同对象的会话里找全并判断 | 有两辆车的用户说“给我的车约保养”，要问是哪辆 |
| 3 主动服务 | 在没有指令时，从看似无关的记忆里发现关联 | 订国际机票时发现护照快过期 |

第三层是“助理”水准的分水岭。它需要同时握有**全局概览**和**精确细节**，这正是 3.3 课“双层记忆架构”要解决的问题。

### 四种存储格式

<div class="anim" data-anim="memory-formats">▶ 动画“同一段对话，四种记法”需要在课程网站中观看。</div>

| 格式 | 长处 | 短处 |
| --- | --- | --- |
| Simple Notes | 开销极低，O(1) 操作 | 关联被割裂 |
| Enhanced Notes | 叙事和语义完整 | 冗余，更新要改多处 |
| JSON Cards | 可部分更新、可预测 | 刚性分类，多维信息难归类 |
| Advanced JSON Cards | person、relationship、backstory、时间戳：能消歧 | 生成和维护更贵 |

**混合使用**：关键且少量的（偏好、人物关系）用 Advanced JSON Cards，大量且非关键的用 Simple Notes。

再往前一步是 **User as Code**：把用户状态写成带类型的对象，把“护照离出发不足 180 天就提醒”写成普通函数。聚合、冲突检测和约束检查交给确定性代码，而不是让 LLM 心算。这和 2.4 课状态栏“用代码维护”是同一个思想。

### 冲突：写入时覆盖，还是只追加？

<div class="anim" data-anim="memory-update">▶ 动画“记忆冲突：写入时覆盖，还是只追加？”需要在课程网站中观看。</div>

Mem0 的演进是本节最值得记住的设计案例：

- **v2（2025）写入时消歧**：每条候选事实先检索相近记忆，再让 LLM 选 ADD / UPDATE / DELETE / NOOP。记忆库始终简洁，但**一次错误的更新会不可逆地丢失历史**，而且每条事实都多一次检索和一次 LLM 调用。
- **v3（2026）只追加、检索时推理**：写入只做 ADD，查询时融合语义、BM25、实体匹配并按时间排序。Mem0 报告 LoCoMo 从 71.4 提升到 92.5。

这和第二章“轨迹只追加”的思路一致：**原始证据只增不改，结论在使用时再算**。

### 整理与隐私

记忆会膨胀，所以需要整理：重要性评分（访问频率、时间衰减、情感强度、独特性）→ 聚类合并 → 从情景记忆中抽象出语义或程序记忆。

隐私方面，书中强调日志脱敏要用**本地模型**：日志本身就含敏感信息，送到云端脱敏违背了初衷。高吞吐场景用混合策略，正则先过滤明显模式，本地小模型处理剩下的自然语言表达（如“我的密码是 abc123”）。

几个值得注意的测试：

| 测试 | 想让你看到 |
| --- | --- |
| `只追加_按时间取当前值_历史仍在` | 新值不覆盖旧值，历史可追溯 |

## 检验（先闭卷回答，再展开）

<details>
<summary>1. 提炼记忆的三条规则分别防止什么问题？</summary>

选择性防止记忆被短期细节塞满；抽象化让一次性的行为变成可复用的长期偏好；结构化让记忆可以被精确检索和部分更新。
</details>

<details>
<summary>2. 为什么“护照快过期”的提醒属于第三层？</summary>

用户没有提问，系统要自己把几个月前存下的护照有效期和这次订的国际机票关联起来，发现风险并主动提出。它既需要全局视野（知道有哪些关键事实），又需要细节（具体日期）。
</details>

<details>
<summary>3. 只追加的记忆库，怎么知道当前值是哪个？代价是什么？</summary>

读取时按时间（以及背景、来源）判断，取最新且仍然成立的那条。代价是记忆库会变大、读取时要多做一些判断；好处是历史不丢，错误的判断可以被纠正。
</details>

<details>
<summary>4. 为什么 mini-agent 把记忆放进系统提示词，却又说“整个会话内不变”？</summary>

系统提示词是静态前缀，改动会让后面的缓存全部失效（2.2 课）。所以记忆在会话开始时渲染一次，会话中产生的新记忆等会话结束后再提炼、写入，下次会话才生效。
</details>

<details>
<summary>5. 为什么日志脱敏要用本地模型而不是云端 API？</summary>

日志本身就可能含敏感信息。为了脱敏把它发到云端，等于先泄露再保护，违背了隐私保护的初衷。
</details>

## 复盘卡

> **原则**：记忆是提炼出的档案，不是聊天记录；提炼要有选择、会抽象、可结构化。
> **设计**：放哪里、怎么存、存什么是三个正交维度；关键信息要带上“为谁、为什么、何时”。
> **底线**：原始证据只追加，冲突留到使用时判断；凭证不进记忆，日志先脱敏。
